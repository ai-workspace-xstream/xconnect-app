# 设计系统扩展：自诊断 / 自修复页面组件

- 关联：#86（自诊断）、#88（自修复）；风格基线见 [`ui-style-system.md`](./ui-style-system.md)；行为设计见 [`network-self-diagnosis.md`](./network-self-diagnosis.md)、[`network-self-repair.md`](./network-self-repair.md)
- 范围：设置页的「诊断」「修复」两个标签。**首页不改动。**
- 平台：桌面端（NavigationRail，内容区最大宽 900）和移动端（底部导航，窄屏）

---

## 0. 参考图与本设计的差异

参考图是网易 UU 的深色「已加速」面板。我们**只借鉴它的信息结构**：

- 顶部：计时 + 节点
- 中部：三块指标 + 链路图
- 底部：结论条 + 「如何处理？」

视觉上一律遵循 XConnect 自己的设计系统：

| 参考图的做法 | XConnect 的做法 | 依据 |
|---|---|---|
| 固定深蓝背景 | 跟随系统浅色/深色主题，使用 `cardBackground` / `surfaceSunken` | 主题 token |
| 数字一律用橙色 | 颜色表示状态：良好 `success`、注意 `warning`、严重 `error`，无数据用 `onSurface` | 颜色要传达含义，不做装饰 |
| 3D 设备插画 | 线性图标：`laptop_outlined` / `smartphone_outlined`、`router_outlined`、`dns_outlined`、`public` | R5：线性图标 |
| 卡片带描边和阴影 | 大卡片保留现有的 `cardBorder` 描边（与 SettingsGroup 一致）；卡片内的小块用 `surfaceSunken` 填充，不加描边；全部零阴影 | R2、R4 |
| 「已加速：00:15:22」 | 「已诊断 00:15:22」 | 这里计的是诊断时长，不是连接时长 |
| 结论条中的「如何处理？」 | 保留，点击后跳到「修复」标签里对应的修复项 | PR1 的按 id 跳转机制 |

## 1. 空间策略：桌面端与移动端

| 断点（设置页内容区宽度） | 典型设备 | 布局 |
|---|---|---|
| **宽屏 ≥ 600** | 桌面窗口，平板横屏 | 指标块用常规尺寸，三块并排；链路图横向，每段标注写成一行；详情直接展开在页内；引导步骤用对话框（宽 480） |
| **紧凑 360–599** | 手机竖屏，窄的桌面窗口 | 指标块用**紧凑尺寸，仍然三块并排**；链路图横向，每段标注拆成两行；详情折叠成「详细信息 ›」；引导步骤用 bottom sheet |
| **极窄 < 360** | 小屏手机，横跨半屏的窗口 | 指标块改成横向的「数值 + 标签」列表行；链路图改为纵向 |

判断依据是 `LayoutBuilder` 给出的**内容区宽度**，不看平台。桌面窗口被拉窄时，也要得到和手机一样的紧凑布局。

> 当前实现的偏差：`live_metrics_panel.dart` 在宽度 < 420 时把三块指标竖着排成一列，每块约 100px 高，在手机上浪费一屏。**按本规格改为紧凑尺寸、三块并排**（见 §3.1）。

**高度预算**（移动端第一屏按 640px 可见高度计算）：

| 区块 | 宽屏高度 | 紧凑高度 |
|---|---|---|
| 页头（计时 + 节点 + 按钮） | 56 | 48 |
| 三块指标 | 120 | 84 |
| 链路图 | 104 | 96 |
| 结论条 | 48 | 48 |
| 合计 | ~360 | **~300** |

紧凑布局下，结论条能在第一屏内看到。

## 2. Token 映射

本次**不新增颜色值**，只给已有 token 定义语义映射。

| 语义 | Token（浅色 / 深色） | 用在哪里 |
|---|---|---|
| 页面底色 | `colorScheme.surface`（`#F3F5F8` / `#0B0F17`） | 设置页背景 |
| 卡片 | `cardBackground` + 1px `cardBorder`，圆角 12（与 SettingsGroup 一致） | 诊断面板、修复分组 |
| 卡片内的小块 | `surfaceSunken`（`#E9EEF4` / `#1A2433`），无描边，圆角 `AppRadius.sm`（8） | 指标块、结论条、命令块 |
| 良好 / 注意 / 严重 | `success` / `warning` / `error` | 数值颜色、链路线颜色、状态圆点 |
| 无数据 | `onSurface`，数值显示为 `— —` | 未开始、预热中 |
| 强调 / 链接 | `brand` | 运行中的计时、「如何处理？」、图标 |
| 冲突提示条 | `warningBannerBackground` / `Border` / `Text` | 其他 VPN 接管网络 |
| 主按钮 | `ink` / `onInk`，`StadiumBorder` | 开始/停止诊断、执行修复 |
| 次要文字 | `mutedText` / `subtleText` | 节点地址、标签、脚注 |

**阈值 → 等级**（与 `live_metrics.dart` 的 `liveVerdict` 一致）：

| 指标 | 良好 | 注意 | 严重 |
|---|---|---|---|
| 延迟 | < 150 ms | 150–299 | ≥ 300 |
| 丢包 | < 2 % | 2–4 % | ≥ 5 % |

**字体**：

| 用途 | 宽屏 | 紧凑 |
|---|---|---|
| 指标数值 | `displaySmall`（30 / w700） | `headlineSmall`（24 / w700） |
| 单位 | `labelLarge`（13） | `labelLarge`（13） |
| 标签 | `labelLarge`，颜色 `subtleText` | 同左 |
| 链路段标注 | `labelMedium` | `labelSmall`（12） |

所有数字都使用 `FontFeature.tabularFigures()`，避免每秒刷新时宽度跳动。

**间距**：沿用 4 / 8 / 12 / 16 / 24。卡片内边距宽屏 16、紧凑 12；块与块之间 16；分组之间 `_groupGap = 24`。

**动效**：数值变化用 `AnimatedSwitcher`（`AppMotion.standard`，220ms）淡入淡出；状态颜色过渡用 `AppMotion.instant`；`MediaQuery.disableAnimations` 为 true 时所有动效时长为 0。

## 3. 新增组件

### 3.1 `DiagMetricTile`（指标块）

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `label` | String | — | 例如「即时延迟」 |
| `value` | String | — | 无数据时传 `— —` |
| `unit` | String? | null | 例如 `ms`、`%` |
| `icon` | IconData? | null | 网络类型块使用 |
| `level` | `DiagLevel` | `none` | 决定数值颜色 |
| `size` | `regular` \| `compact` \| `row` | 由宽度决定 | 见 §1 |

| 尺寸 | 布局 |
|---|---|
| `regular` | 竖排：数值 + 单位，下面是标签；最小高度 104 |
| `compact` | 同 `regular`，数值改用 `headlineSmall`，内边距 12，最小高度 76 |
| `row` | 横排：左边标签，右边数值 + 单位；高度 44，最小触控高度 |

| 状态 | 表现 |
|---|---|
| 无数据 | 数值显示 `— —`，颜色 `onSurface` |
| 预热中 | 数值用 `mutedText` 显示，外层 `Semantics` 注明「采样中」 |
| 有值 | 按 `level` 着色 |

无障碍：整块合并成一条朗读，例如「即时延迟 162 毫秒，注意」；单位要读成文字，不读符号。

### 3.2 `DiagPathView`（链路图）

作用：显示「本设备 → 路由器 → 节点服务器（→ 目标站点）」每一段的延迟和丢包，并**标出问题出在哪一段**。

| 属性 | 类型 | 说明 |
|---|---|---|
| `nodes` | `List<DiagPathNode>` | 每个节点有 `kind`（device / router / server / target）和 `label` |
| `segments` | `List<DiagSegment>` | 每段有 `latencyMs?`、`lossRate?`、`level`、`state` |
| `culpritIndex` | int? | 主因所在的段 |
| `axis` | `horizontal` \| `vertical` | 由宽度决定 |

段的状态（`state`）：

| state | 线条 | 标注 |
|---|---|---|
| `measured` | 实线，颜色按等级 | 「3 ms · 丢包 10%」（宽屏一行，紧凑两行） |
| `culprit` | 实线加粗到 3px，颜色按等级 | 标注加粗，前面加 `!` |
| `warmingUp` | 虚线，`cardBorder` 色 | 「采样中」 |
| `unmeasurable` | 虚线，`cardBorder` 色 | 「无法测量」（例如路由器不响应探测；**绝不能显示成 100% 丢包**） |
| `notConnected` | 虚线 | 「未连接」（例如隧道没开时的 S3 段） |

节点：图标 24，放在 40×40、圆角 8、`surfaceSunken` 底色的方块中；名称用 `labelLarge`，单行，放不下时省略。

- 本设备在桌面端用 `laptop_outlined`，在手机上用 `smartphone_outlined`。
- 目标站点（S3 段）只在隧道已连接时显示。未连接时链路图只有三个节点，和参考图一样。

无障碍：每一段单独朗读，例如「本设备到路由器，延迟 3 毫秒，丢包 10%，问题所在段」。

### 3.3 `DiagStatusBar`（结论条）

| 属性 | 说明 |
|---|---|
| `level` | 圆点颜色和文字颜色 |
| `text` | 结论文案，例如「您当前设备的网络环境不稳定」 |
| `actionLabel` / `onAction` | 可选，例如「如何处理？」 |

- 布局：圆点 8 + 文字 `bodyMedium`（w600），右侧是 `brand` 色的动作链接。
- 在紧凑布局下，**整条都可以点击**：高度 ≥ 48，右侧显示 `chevron_right`，文字最多两行。
- 结论变化时用 `liveRegion` 播报，只在结论**变化**时播报，不要每秒播一次。
- 修复页顶部的「冲突检查」摘要也复用这个组件。

### 3.4 `InlineBanner`（页内提示条，从现有的临时实现提升为正式组件）

| variant | Token | 用途 |
|---|---|---|
| `warning` | `warningBanner*` | 其他 VPN 或加速器在接管网络；检测到手动 DNS |
| `info` | `brandMuted` 底色 + `brand` 图标 | 例如「MAS 版不能直接修改系统设置，请按步骤操作」 |

结构：图标 18 + 标题（w600）+ 正文，可选一个文字按钮。圆角 8，内边距 12。

### 3.5 `RepairActionRow`（修复项，在 `SettingsRow` 基础上扩展）

| 属性 | 说明 |
|---|---|
| `icon` / `title` / `description` | 与 SettingsRow 相同 |
| `mode` | `inApp`（一键修复）、`guided`（引导操作）、`admin`（需要管理员授权），显示为一个徽章 |
| `status` | `idle` / `running` / `done` / `failed` / `rolledBack` |
| `onRun` | 执行修复 |

- 徽章 `ExecutionModeBadge`：pill 形状，`labelSmall` 字号；颜色 `inApp` 用 `brandMuted`，`guided` 用 `surfaceSunken`，`admin` 用 `warningMuted`。
- 宽屏布局：图标 | 标题、说明和徽章 | 右侧按钮（`ink` pill，文字是动词，例如「清理」「修复」「查看步骤」）。
- 紧凑布局：按钮换成 `chevron_right`，点整行打开确认面板或引导面板。

| status | 表现 |
|---|---|
| `running` | 按钮换成 16px 的转圈，整行不可点（沿用 `SettingsRow.busy`） |
| `done` | 显示 `check_circle_outline`（success 色）和「已修复 · 可撤销」链接，保留 10 秒 |
| `failed` | 显示 `error_outline`（error 色）和「已回滚」说明，以及「查看详情」 |

### 3.6 `RepairSheet`（确认面板 / 引导面板）

宽屏用对话框（宽 480），紧凑布局用 bottom sheet。共有两种：

| 类型 | 内容 |
|---|---|
| **确认**（`inApp` / `admin`） | 「将要修改」的前后对照表（例如 Wi‑Fi 的 DNS：`1.1.1.1, 8.8.8.8` → 自动获取）；一行说明「修改前会备份，可一键撤销」；按钮「取消」「修复」（使用动词，不用「确认」） |
| **引导**（`guided`） | 编号步骤；可选「打开系统设置」按钮（深链）；可选命令块（等宽字体，`surfaceSunken` 底色，右上角复制按钮，默认折叠在「高级」里）；主按钮「我已完成，重新检查」 |

## 4. 页面组成

### 4.1 设置 → 诊断

```
宽屏 ≥600                                   紧凑 360–599
┌──────────────────────────────────────┐   ┌─────────────────────────┐
│ 已诊断 00:15:22            [停止诊断]  │   │ 已诊断 00:15:22  [停止] │
│ jp · jp-xhttp.svc.plus:443            │   │ jp-xhttp.svc.plus:443   │
│ ⚠ 检测到其他 VPN 或加速器正在接管网络   │   │ ⚠ 其他 VPN 正在接管网络 │
│ ┌────────┐ ┌────────┐ ┌────────┐      │   │ ┌─────┐┌─────┐┌─────┐  │
│ │ 162ms  │ │  10 %  │ │  Wi‑Fi │      │   │ │162ms││ 10% ││Wi‑Fi│  │
│ │即时延迟│ │ 丢包率 │ │网络类型│      │   │ │延迟 ││丢包 ││网络 │  │
│ └────────┘ └────────┘ └────────┘      │   │ └─────┘└─────┘└─────┘  │
│ ▢本设备 ─3ms·丢包10%─ ▢路由器 ─158ms─ ▢节点│ │ ▢ ─3ms──▢ ─158ms─▢     │
│ ● 您当前设备的网络环境不稳定  如何处理？ │   │ │     丢包10%    丢包0% │
│ 详细信息（网关、DNS 耗时、节点…）       │   │ ● 网络环境不稳定     ›  │
└──────────────────────────────────────┘   │ 详细信息              ›  │
                                           └─────────────────────────┘
```

- 按钮位置：宽屏在右上角；紧凑布局仍在右上角，但只显示一个字（「停止」），以节省高度。
- 移动端**不自动开始**：进入标签后要用户点「开始诊断」，由此触发本地网络权限的弹窗（见诊断设计 §1.2）。
- 离开标签、App 进入后台，或连续运行 5 分钟，都会自动停止。

│ ✓ 系统代理正常                              │   ├──────────────────────────┤
├───────────────────────────────────────────┤   │ 一键修复                 │

│ 需要你手动处理（1）                         │   │ 修复记录               › │

- **不同平台显示不同的修复项**：列表由执行模式决定（见 `network-self-repair.md` §3、§4）。
  - MAS 版 macOS 和 iOS 上，「修复 DNS」显示为「引导操作」。
  - 直装版 macOS、Windows 和 Linux 上，显示为「一键修复」或「需要管理员授权」。
- **第三方组件只显示「查看」**，永远不提供「修复」按钮（红线：不动其他厂商的组件）。
- 在紧凑布局下，「需要你手动处理」和「修复记录」折叠成两个导航行，节省首屏空间。

## 5. 可访问性汇总

| 项 | 要求 |
|---|---|
| 焦点顺序 | 主按钮 → 冲突提示条中的动作 → 指标块 → 链路图各段 → 结论条动作 → 详情 |
| 触控目标 | 移动端最小 44×44（紧凑布局下整行、整条可点就是为了满足这一点） |
| 颜色以外的提示 | 严重的段加粗并加 `!`；结论条的图标形态也随状态变化 |
| 播报 | 只在结论变化时播报；数值不播报 |
| 大字号 | 系统字号放大到 200% 时，紧凑布局的指标块自动退回 `row` 尺寸 |
